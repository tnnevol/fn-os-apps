# FNOS-001 真实环境验收记录（fnos-mi，2026-10-20）

本记录是 [FNOS-001 1Panel 应用商店应用转换](/requirements/FNOS-001-1panel-app-conversion) 在
**fnos-mi** 设备上的目标环境验收记录，用例定义见
[FNOS-001 1Panel 应用转换测试用例](/testing/FNOS-001-test-cases)，格式规范见
[真实环境验收记录](/validation/README)。

前序记录：[FNOS-001 真实环境验收记录（2026-10-09）](/validation/FNOS-001-fnos-nas-2026-10-09)，
该轮因设备端 `appcenter-cli` 权限阻塞而停在部分 AC。

## 0. 本轮与前序记录的关键差异

| 维度 | 2026-10-09（fnos-nas） | 2026-10-20（fnos-mi） |
| --- | --- | --- |
| 验证通道 | 设备端 `trim-cli` / `appcenter-cli` | **Midscene 驱动 fnOS Web UI**（`appcenter-cli` 仍不可用） |
| 设备地址 | ${FNOS_HOST} | ${FNOS_HOST} |
| 可执行动作 | 安装、启停 | 安装、启停、**卸载向导**、**端口占用场景**、入口地址核验 |
| 覆盖 AC | 04-AC-02 通过、04-AC-03 部分通过 | 04-AC-02 / 04-AC-03 / 04-AC-05 / 04-AC-06 通过 |

**为什么换通道**：`appcenter-cli` 在目标设备上启动即 panic
（`ApplyPermission for '[com.trim.sysinfo com.trim.main]' error, dial unix /run/trim_app_cgi/rpcbroker: connect: permission denied`），
设备端安装链路整体不可用；而 fnOS 应用中心的**手动安装**功能在 Web UI 上完全可用，
因此改用 Midscene 复用已登录的 Chrome 驱动 UI 完成同一批验收动作。

### FNOS-001-04-AC-06：端口占用处理

场景构造：先让 `fn-it-tools` 占用 40116，再把 `fn-web-check` 的向导端口改为 **40116**。

| 步骤 | 预期结果 | 实际结果 | 状态 |
| --- | --- | --- | --- |
| `fn-web-check` 手动安装 → 同意 → 端口配置 | 进入端口向导 | 「安装 Web-Check – 基础配置」，默认端口 40095 | 通过 |
| 将端口改为 40116 并「下一步」 | 允许进入安装（向导静态校验不判定运行时占用） | **未在表单阶段拦截**，进入安装流程 | 通过（符合设计） |
| 安装完成 → 应用中心「已安装」 | 不得出现「显示运行中但实际不可访问」 | **Web-Check 卡片按钮显示「启用」= 未运行**；同列表 IT-Tools 显示「打开」= 运行中 | 通过 |
| 应用详情页 | 状态与列表一致 | Web-Check 详情：版本 6.0.0、来源「手动安装」、按钮为「启用」 | 通过 |

**结论**：AC-06 的两条通过路径中命中**第二条**——「安装后 `cmd/main status` 返回非 0 使应用中心显示未运行」。
硬性红线（安装成功且显示运行中但实际不可访问）**未触碰**。

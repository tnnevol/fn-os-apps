#### 卸载（删除数据）真机结果 — 2026-10-10 由用户在应用中心执行

CLI 侧无法完成卸载（`app uninstall` 拒绝：`requires custom wizard parameters`；该子命令不提供 `--custom-parameters`；`raw` 对 `appcgi.appcenter.*` 全部 403；直接 curl `/app-center/v1/uninstall/info` 返回 401，因 CLI 使用了带签名的 CGI 通道而 session 中无 `secret` 可复现）。**改由用户在应用中心 UI 手工卸载并选择「删除所有数据」**，随后核验：

| 核验项 | 结果 |
| --- | --- |
| 应用中心移除 | `app status fn-it-tools` → `installed app not found`；已装列表 37 项，不含该应用 |
| 端口释放 | `curl http://${FNOS_HOST}:40116/` → `HTTP 000`（连接失败） |
| 安装目录 | `/var/apps/fn-it-tools` 已移除 |
| **数据目录** | `/vol4/@appdata/fn-it-tools`、`/vol4/@apphome/fn-it-tools`、`/vol4/@appmeta/fn-it-tools` 均仍存在但 **`du -sb` 占用为 0 字节**（对照：已装的 `@appdata/fn-bitwarden` 为 8）；`@apptemp/fn-it-tools` 已完全删除 |

**这一结果与 `cmd/uninstall_callback` 的 delete 分支行为一致**：脚本删除 `${TRIM_PKGVAR}`（= `/vol4/@appdata/fn-it-tools`）与 `${TRIM_PKGHOME}`（= `/vol4/@apphome/fn-it-tools`），使两者归零；残留的空目录由应用中心框架自身管理，非脚本遗留数据。

**结论边界（不夸大）**：本项证明的是「用户在 UI 选删除数据后，应用与数据确实被清除」，**未取得脚本 stdout 日志作为直接证据**（应用中心日志目录 `/var/log/trim_app_center/` 无读权限，`logger` 模块不含应用中心，`file search` 接口不可用）。因此**不能断言「删除动作确由我们的脚本执行」**；但因删除范围与脚本逻辑完全吻合，判定为**行为符合预期**。

**仍未验证**：卸载时选「保留数据」后重装读回。该分支需重新安装并再走一次卸载流程。本地已用构造目录验证该脚本的 keep/delete 与 `${VAR:?}` 空变量守卫（见本文档「单应用端到端复跑」第 11 项）。

#### 端口冲突处置

`fn-cyberchef` 与 `fn-wechatmarkdowneditor` 上游默认端口**都是 8080**。安装前检查发现 8080 空闲，故第一个用默认值、第二个改用 8081。**这验证了规约「端口冲突由用户在向导里改」的路径可用**——安装向导确实接受自定义端口，且入口随之指向新端口。

#### `fn-wechatmarkdowneditor` 验证了入口 ID 规则

该应用 app 名 20 字符，`fn-wechatmarkdowneditor.Application` = 35 字符 **超过 fnpack 的 32 字符硬上限**，故按规约改用 `.main` 后缀（28 字符）。真机证据：桌面入口的 `fnDomain` 为 **`fn-wechatmarkdowneditor-main`**（不是 `-application`），证明 `.main` 形态在设备端被正确接受与注册。这是该规则**首次在真机得到验证**。

#### `fn-web-check` 安装失败（待 UI 清理）

**现象**：`app install-fpk` 返回 `timed out waiting for app-center install task`；随后核查发现 `/var/apps/fn-web-check/` 目录**已完整解包**（`cmd`/`config`/`manifest`/`wizard`/`ICON*.PNG` 齐全，`target` 指向 `/vol4/@appcenter/fn-web-check` 且内含 `config`/`docker`/`ui`），但应用**未出现在已装列表**（`app status` → `installed app not found`），端口 40095 未监听。

**重试**：`app install-fpk` 再次执行 → `App Center code 10500: status operation is not supported for the app in its current state`。

**处置尝试**：`app install-cancel <taskId>` 返回 `Canceled app-center install task fn-web-check`，但**残留状态未被清除**，重试仍报 10500。

**对照**：同一批次、同一路径、配置与 `fn-cyberchef` 完全同构的 `fn-wechatmarkdowneditor` 安装成功，说明**不是转换产物的问题，而是 App Center 侧的残留安装状态**。

**结论**：`fn-web-check` 的失败**不能归因于 FPK 或转换质量**；需在 **App Center UI** 中清理该应用的残留状态（应用应当以某种中间态存在于后端，CLI 的 `install-cancel` 不足以复位），之后重装验证。**未验证该应用的真机可用性。**

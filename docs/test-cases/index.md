# 测试用例规范

本规范用于将中文需求文档和验收条件转换为可执行、可追溯、可评审的测试用例。测试用例生成遵循 `qa-req2testcase-generator` Skill V4.15.56 的分段流程和质量门禁。

## 文档职责

| 文档 | 负责内容 |
| --- | --- |
| [需求清单](/requirements/) | 说明要解决的问题、范围和验收条件 |
| [详细计划](/plans/) | 说明实现方案、测试策略和发布要求 |
| 测试用例 | 说明具体操作步骤、前置条件、预期结果和执行结果 |
| [真实环境验收记录](/validation/README) | 记录 NAS、FPK 和发布环境的实际验收证据 |

## 适用范围

- 仅支持中文需求正文、中文 `.docx`、`.txt` 或等价的中文需求文档。
- 需求载荷必须在生成流程开始前提供；只有 Skill 名称或模糊描述不能作为需求输入。
- 图片、流程图和原型图属于需求上下文；没有图片理解能力时，必须明确标记为纯文本推断，不能伪造图片结论。
- 测试用例用于验证需求，不替代业务代码、单元测试或真实环境验收记录。

## 用例编号和字段

用例编号使用 `<功能编号>-TC-##`，例如 `FNOS-002-01-TC-01`。每条用例必须能回溯到需求功能或验收条件，并至少包含：

| 字段 | 要求 |
| --- | --- |
| 用例编号 | 唯一、稳定，不能因排序变化而重复使用 |
| 关联需求/验收 | 指向需求功能编号和具体验收条件 |
| 前置条件 | 写明账号、权限、数据、服务和环境状态 |
| 操作步骤 | 一步一个动作，使用可复现的具体操作 |
| 预期结果 | 描述可观察结果，不使用“正常”“符合预期”等空泛表述 |
| 优先级 | P0 冒烟、P1 主流程、P2 扩展或边界 |
| 测试环境 | 本地、浏览器、FPK 或真实 fnOS NAS 等 |
| 执行结果 | 未执行、通过、失败或阻塞，并附证据 |

## 六段生成流程

测试用例生成必须按段落推进，每次确认只进入一个段落；段落结束后暂停，等待下一次明确确认。

| 段落 | 内容 | 主要产物 | 结束条件 |
| --- | --- | --- | --- |
| 1 | 初始化和 onboarding | 任务状态、配置和用户偏好 | PRD 审查、知识库和图片能力选择完成 |
| 2 | 需求结构化和图片理解 | 需求结构、图片上下文 | 需求功能、范围和验收条件可追溯 |
| 3 | 功能拆解与初步测试点 | 功能树、测试点草案 | P0/P1 功能覆盖完成 |
| 4 | 风险与 PCI 场景 | 风险测试点、异常和兼容场景 | 风险点与主流程建立关联 |
| 5 | 测试点合并与逐条用例生成 | 测试用例 JSON/Markdown | 每条用例通过结构和内容检查 |
| 6 | 质量检查与导出 | 质量门禁结果、Excel/Markdown | P7 通过后才能发布用例 |

不得跳过段落、预读下一段规则或直接手写 gate/output 文件。涉及批量生成时，必须遵循 Skill 的逐条生成规则，不使用脚本循环或子代理代替主流程生成。

## 质量门禁

- 需求、功能、测试点和用例之间必须保持可追溯关系。
- 用例步骤必须具体，不能使用占位符、空泛结果或无法执行的描述。
- 正常流程、空数据、失败、权限、超时、重复操作和兼容性场景按需求适用范围覆盖。
- P0 只用于入口可达性、核心数据加载展示和核心操作完成；不得将异常、删除、禁用或纯 UI 细节标为冒烟。
- P0 占比控制在 10%–15%，冒烟用例不能为 0。
- 合并后重复率不得超过质量门禁要求；发现重复、空洞步骤或缺少上下文时必须修复后重新合并和检查。
- 报告中的总数、优先级分布、冒烟数和去重率必须直接来自生成器的 `statistics`，不得估算或手工编造。
- 任何生成错误或质量拒绝都必须按错误信息修复重试，不能伪造通过结果。

## 环境和验收边界

- 共享包、插件和业务代码使用各自的单元测试验证；测试用例生成结果不能替代单元测试。
- 涉及 fnOS、权限、FPK、网关、插件加载、升级或回滚的用例，必须区分本地验证和真实 NAS 验证。
- 本地构建通过不能作为 NAS 验收结论；真实结果必须记录到[真实环境验收记录](/validation/README)。
- 需求完成状态以目标环境验收为准，并同步回写需求文档和计划文档。

## 测试用例模板

```markdown
### FNOS-002-01-TC-01 用例名称

- 关联需求：FNOS-002-01
- 关联验收：<验收条件编号>
- 优先级：P0 / P1 / P2
- 环境：本地 / fnOS NAS
- 前置条件：
  1. ...
- 操作步骤：
  1. ...
- 预期结果：
  1. ...
- 执行结果：未执行 / 通过 / 失败 / 阻塞
- 证据：日志、截图或验收记录链接
```

真实 NAS 的执行结果应另行记录到[真实环境验收记录](/validation/README)，并回写对应需求和计划的状态。

## 需求背景与目标

DeepSeek Harness（DSH）原生面向通用 Node.js 和浏览器环境。作为 fnOS 应用运行时，它需要通过 iframe 进入 NAS 桌面，并同时处理应用生命周期、持久化目录、统一网关和 fnOS Web SDK 的宿主差异。如果这些能力直接散落在 DSH 页面或修改官方源码，后续升级会难以维护，也无法复用到其他 fnOS 能力中。

本需求建立一个专门面向飞牛 NAS 的 DSH 适配层：由 `fn-deepseek-harness` 提供应用运行边界，由 `@tnnevol/dsh-fnos` 和 `@tnnevol/dsh-codex-auth` 提供插件能力。适配层应保持 DSH 官方功能和数据结构不变，只在 fnOS 宿主中增加必要的桥接、授权和 Codex 登录能力。

## 需求目标

- 让 DSH 在 fnOS iframe 应用中稳定启动、访问和持久化运行。
- 将 fnOS 与 Codex 适配能力集中在独立插件中，避免修改官方 DSH 源码；只有已发布并进入 FPK 发布清单的插件才通过 npm 自动集成，未发布插件不进入 FPK。
- 让 DSH 的“跟随系统”主题跟随 NAS，用户明确选择浅色或深色时仍以 DSH 配置为准。
- 让用户能够管理 DSH 访问 NAS 所需的授权目录，并为后续工作区能力保留清晰的授权边界。
- 在工作区选择弹框中提供跳转到已授权 fnOS 目录的快捷入口，授权目录较多时仍能快速检索和定位。
- 在 DSH 内容输入框右下区域提供选择 NAS 目录和文件的快捷入口，将选择结果作为输入引用回填。
- FPK 安装阶段按发布清单自动集成插件：通过安装向导选择的 npm 源安装精确版本，未发布插件不在构建阶段编译、打包或复制到 DSH Web profile。
- 为后续接入其他 fnOS JS SDK 能力保留清晰的 Host、Client 和应用权限边界。

## 交互和行为约束

### 主题

- 进入 fnOS 应用时读取 NAS 当前主题作为初始状态。
- 只在 DSH 主题设置为“跟随系统”时响应 NAS 主题变化。
- 使用 fnOS SDK 的主题事件监听，不增加轮询兜底。
- DSH 保持 `system` 偏好不变；真实 fnOS Web 宿主可写入当前生效的 NAS 主题缓存，下一次 Web profile 首屏由 Host 优先使用缓存，避免浏览器系统主题造成闪烁。
- DSH 显式选择浅色或深色时不写入 NAS 主题缓存，并清理旧缓存。由于 fnOS SDK 只返回 `light`/`dark` 最终值，未提供 NAS“跟随系统”偏好字段，无法在插件侧区分 NAS 的显式选择和跟随系统后的相同最终值。
- 在独立浏览器运行 DSH 时找不到 fnOS SDK，适配层应安全降级，不阻塞 DSH 工作台。

### fnOS 宿主页面标题

- 在 fnOS Web 宿主 iframe 中等待 NAS JS SDK 初始化完成后读取 DSH 的 `document.title` 并调用 `setTitle(document.title)`。
- 监听 `<title>` 元素变化，使会话标题切换后同步更新 fnOS 宿主标题。
- 独立浏览器和非 Web 宿主环境不调用标题 SDK，保持 DSH 原有页面标题行为。
- SDK 初始化或标题更新失败时只记录调试信息，不阻塞 DSH 工作台。

### 授权目录

- 入口文案统一使用“授权目录”。
- 展示已授权目录，并提供“添加授权目录”入口。
- 授权目录变化成功后立即重新查询真实授权结果，不设置虚假的保存、取消或恢复按钮。
- 授权列表合并 `TRIM_DATA_ACCESSIBLE_PATHS`、`TRIM_DATA_SHARE_PATHS`、应用默认安装目录族（`@app`、`@apphome`、`@appshare`、`@appdata`、`@appconf`）与 fnOS 授权 API 后去重，并使用 `trim.file.convertPath` 展示可读路径。
- `TRIM_DATA_SHARE_PATHS` 中的应用共享目录仅用于展示，不显示删除/取消授权入口，也不调用取消授权 API。
- 取消目录选择器、关闭弹框或 SDK 按 `AppBridgeResponse<string[]>` 返回 `code: 0` 且 `data: []` 时静默结束；授权选择器流程不在配置面板显示通用错误提示，详细结果只写入调试日志。
- 删除前必须明确提示“只取消应用访问权限，不删除文件”。
- 普通用户可以查看授权结果；添加和删除操作由 fnOS 权限控制。

### FPK 安装阶段集成插件

- FPK 只打入已发布插件的精确版本清单和通用安装脚本，不复制任何插件工作空间源码或本地构建产物。
- `cmd/install_callback` 在 DSH Web profile 尚未初始化时先完成初始化，再使用安装向导选择的 npm 源安装发布清单中的插件，并将包加入 `dsh.profile.bundles`。
- 升级流程按清单从 npm 更新已发布插件；应用启动只校验清单插件的精确版本和 bundle 声明，不因每次启动联网。
- 安装和升级流程必须可重复执行，不能覆盖用户的 DSH 配置、会话、凭据或其他 profile 数据；安装器只维护官方 bundle 基线和发布清单中的插件，不对 `@tnnevol/dsh-fnos` 执行本地依赖迁移、删除或补丁操作；npm 安装失败时应用安装/升级失败并输出明确日志。
- FPK 安装完成后，发布清单中的插件应能随 `dsh web` 自动加载；未发布插件不属于 FPK 自动安装范围。

### 工作区快捷跳转授权目录

- 保留 DSH 原始工作区选择弹框、菜单、关闭和选中后的跳转逻辑；插件只占用官方公开的 `conversation.hero.workspace.directoryFlow` 与 `sidebar.workspaces.directoryFlow` 子流程插槽。
- 目录流程保留 DSH 原始路径输入、目录列表、目录打开、确认和取消行为；工作区入口使用同一授权范围，但只展示当前真实存在且当前用户可读的目录，并进行规范化去重；列表展示语义路径，内部保留对应真实路径。
- 授权目录超过 10 个时显示搜索输入，可按语义路径或真实路径检索；少于等于 10 个时直接展示目录列表。
- 在 DSH 原始路径输入旁增加无文字的主题感知黑白 fnOS logo 按钮；点击后打开插件自己的授权目录列表面板，选择结果写回原始路径输入框，再交给 DSH 原始 `onPicked`。
- 工作区快捷入口不调用 fnOS SDK 目录选择器，不申请 ACL；只能选择已经授权的目录或应用共享目录。
- DSH 收到 `onPicked` 后，已有路径复用已有工作区，尚未登记的路径由 DSH 原生流程登记为工作区，再打开对应工作区；插件不修改 ACL、不复制文件、不改变会话数据。
- 授权被撤销、目录不存在或真实路径不可访问时保留原始弹框并显示可理解的错误；取消列表面板、关闭弹框和取消确认不产生额外红色提示。

### 内容输入框选择 NAS 目录和文件

- 在 DSH 内容输入框右下操作区域增加有颜色的 fnOS 官方 logo 按钮，使用彩色官方 logo，不与工作区入口共用黑白图标资源。
- 点击按钮后打开插件自己的 DSH 风格授权路径面板，通过同源 Host 路由列出授权根目录及其下一级文件/目录；不调用 fnOS SDK，也不出现“选择文件/选择目录”的二级面板。
- 支持在授权范围内进入目录并多选文件和目录，选择结果在输入框文案上方的引用区合并展示。目录使用文件夹 icon、文件使用文件 icon；选项较多时堆叠展示，鼠标移入后展开到输入框可用的最大宽度并支持横向滚动。
- 每个已选项支持移除；按规范化真实路径去重，不允许同一文件重复选择。选择成功后插入 DSH 原生引用占位，展示文案保留可读的语义路径；提交或复制时由引用 codec 生成 URL 转义后的真实 `file:///...` 路径。
- 不自动上传、复制或移动 NAS 文件；选择结果只作为 DSH 支持的路径/文件引用。
- 选择面板取消、关闭或返回空结果时静默结束；Host 路由不可用、权限不足或读取失败时保留可理解的错误状态和重试入口。
- 按钮和选择器应适配浅色、深色和 fnOS iframe 宿主；独立浏览器缺少 fnOS SDK 时安全降级，不阻塞 DSH 内容输入。

### 上下文文件访问

- 不增加新的文件打开按钮，继续使用 DSH 现有上下文文件、工具结果和生成文件路径的点击入口。
- DSH 将相对路径解析为工作区对应的真实路径后调用统一的 `workspaces.openPath(path)`；`@tnnevol/dsh-fnos` 在 fnOS iframe 内装饰这个公开服务入口。
- 在 fnOS iframe 内，插件直接调用 `TrimApp.openFile(path)`，由 fnOS 文件应用和当前用户权限执行最终判断；不再先通过 Host 同源路由依据插件展示的授权根拦截路径。
- 授权目录列表只用于展示和选择，不作为打开路径前的最终权限结论；避免列表延迟、路径转换差异或 NAS 实际 ACL 已更新时误拦截合法路径。
- 打开目录或文件均交给 fnOS 文件应用处理；插件不调用、不安装也不依赖 Linux `xdg-open`，避免 NAS 环境缺少该命令导致 `ENOENT`。
- fnOS SDK 拒绝打开或文件应用打开失败时提示可理解的错误并保留重试；取消或关闭授权入口不产生额外红色权限提示。
- 在独立浏览器或本地 DSH 调试环境中，插件不执行 fnOS 授权校验，继续调用 DSH 原生打开逻辑，不影响官方本地调试。

#### 用户交互流程

```text
用户点击 DSH 上下文/工具结果/生成文件中的路径
  └─ DSH 解析工作区相对路径并调用 workspaces.openPath(真实路径)
       ├─ 独立浏览器：继续使用 DSH 原生打开逻辑
       └─ fnOS iframe：直接调用 TrimApp.openFile(真实路径)
            ├─ fnOS 文件应用和当前用户权限执行最终判断
            ├─ 文件/目录打开成功：返回 DSH 页面
            └─ fnOS SDK 拒绝或打开失败：显示可理解错误并保留重试入口
```

交互约束：

1. 用户继续点击 DSH 原有路径链接，不增加第二个打开按钮，也不要求复制 NAS 内部路径。
2. 取消授权目录选择器、关闭弹框或返回空结果时静默结束，不出现“只有 NAS 管理员可以授权目录”等红色提示。
3. 真实路径只用于 Host 校验和 fnOS 打开调用；Host 同时检查实际文件状态与当前网关用户 ACL，不展示 Token、Socket 或内部堆栈。
4. 打开文件或目录不修改 DSH 工作区、会话、配置和 NAS 文件内容。

## 不在本次范围内

- 不修改 DeepSeek Harness 官方源码，不向官方仓库提交适配代码。
- 不改变 DSH 的 `HOME`、`DSH_HOME`、`@appshare` 数据布局和已有会话数据。
- 不因取消授权删除目录、文件、工作区记录、会话或其他用户数据。
- 不通过插件重写 DSH 的 memory 模式、官方插件加载机制或模型业务逻辑。
- 不使用轮询模拟 fnOS 主题事件，也不在浏览器端暴露 `TRIM_API_TOKEN`。
- 不在本需求中一次性接入所有 fnOS JS SDK；每项新增 NAS 能力都应有独立需求和计划。
- 替换整个 DSH 工作区菜单、限制所有工作区只能落在授权根目录内，不属于本次需求范围；FNOS-001-10 只替换原始弹框内部的公开目录流程，不修改官方 DSH 源码，并保留 DSH 原生工作区登记/复用语义。
- 不在 FNOS-001-11 中实现文件上传、文件复制/移动、NAS ACL 修改或会话附件持久化策略；这些能力如需接入应另立需求。
- FNOS-001-11 首期不支持多选结果的批量上传或会话附件持久化；多选仅用于生成 DSH 可消费的路径/文件引用。
- FNOS-001-12 不修改 DSH 官方文件打开实现，不通过安装 `xdg-utils` 解决 NAS 缺少 `xdg-open`，也不绕过 fnOS 授权目录边界。

## 验收条件与完成状态

### P0 待完成验收

代码实现和本地环境验证已经完成，但插件尚未进入真实 fnOS NAS 环境完成安装、启动和主题事件验证。因此 P0 暂不标记为已完成，以下条件均需在真实 NAS 环境验收后关闭：

- fnOS 应用可从 NAS 桌面打开，iframe 页面能够访问 DSH Web。
- NAS 主题切换事件能够更新处于“跟随系统”的 DSH 页面。
- DSH 手动选择浅色或深色时，NAS 主题切换不会覆盖用户选择。
- 没有 fnOS SDK 的裸 DSH 环境仍可正常运行。

### P1 FPK 集成 DSH 插件验收

发布清单和通用 npm 安装/校验流程已经完成，但尚未在真实 fnOS NAS 环境完成插件自动加载验证，因此该 P1 暂不标记为已完成：

- `@tnnevol/dsh-codex-auth` 按发布清单从 npm 安装；未发布的 `@tnnevol/dsh-fnos` 不进入 FPK，也不修改官方 DSH 源码。

- 重复安装、升级和应用启动不会重复写入异常 bundle，也不会丢失用户 profile 数据、配置、会话或凭据；安装器不再对 `@tnnevol/dsh-fnos` 执行本地依赖迁移、删除或旧补丁清理，避免把 fnOS 插件与 FPK 的通用发布插件流程耦合。

### P1 授权目录待真实 NAS 验收

Host/Client 实现、应用 Scope、环境变量合并、语义路径转换、取消静默和本地构建已经完成，但尚未在真实 fnOS NAS 环境完成权限和删除行为验收。因此 P1 暂不标记为最终完成：

- 管理员可以看到当前应用已授权目录，并能通过目录选择器新增目录。
- `TRIM_DATA_SHARE_PATHS` 中的应用共享目录与 ACL 目录一起展示，且没有删除/取消授权按钮。
- 新增授权成功后，授权目录卡片立即反映真实结果；取消或空授权结果不显示红色权限警告。
- 删除授权只移除应用 ACL，不删除目录和文件。
- fnOS API 返回未授权、路径不存在或网络错误时，页面显示可理解的错误并保留重试入口。
- Host 侧不向 Client 返回 Token、Unix Socket 等敏感运行信息。

### FNOS-001-10 工作区快捷跳转代码完成，待真实 NAS 验收

该功能已经接入 DSH 原始工作区弹框的公开目录流程插槽，并完成本地构建验证，尚未进入真实 fnOS NAS 验收：

- DSH 原始工作区选择菜单和弹框仍由官方组件负责，插件通过 `conversation.hero.workspace.directoryFlow` 与 `sidebar.workspaces.directoryFlow` 提供目录流程。
- 目录流程保留 DSH 原始路径输入、目录列表、目录打开、确认和取消行为；展示有效授权目录，超过 10 个目录时出现搜索。
- 路径输入旁的黑白 fnOS logo 打开插件授权目录面板；选择结果写回原始路径输入，再通过 DSH 原生 `onPicked` 复用或登记工作区并打开，不修改 ACL、文件或会话数据。
- 该入口不调用 fnOS SDK 目录选择器；取消时静默结束，加载失败、授权目录失效和路径确认失败保留可理解的错误状态。
- fnos 插件只使用 DSH 公开的目录流程插槽，不通过应用 bundle 禁用或替换官方目录选择器，也不修改官方 DSH 源码；官方目录流程与 fnOS 目录入口的兼容性由真实 NAS 验收确认。

### FNOS-001-11 内容输入框 NAS 选择代码完成，待真实 NAS 验收

已完成插件侧实现和本地验证，尚未进入真实 fnOS NAS 完成选择器、路径转换和提交链路验收：

- 插件自有路径面板支持多选 NAS 目录和文件，只显示授权根目录范围内的内容；输入框文案上方使用文件夹/文件 icon 展示已选项，选项较多时堆叠展示，悬停展开到最大可用宽度并支持横向滚动。
- 已选项支持移除，规范化真实路径去重，不允许同一文件重复选择；Host 通过 `/plugins/dsh-fnos/paths/convert` 转换可读路径，DSH 引用 codec 在提交/复制时生成 URL 转义后的真实路径。
- 选择结果通过 DSH 原生 `ReferenceInsert` 插入，不写入 DSH 配置，也不上传或复制文件。
- 取消选择不产生误提示；Host 路由不可用、权限不足和读取失败场景可理解且不阻塞普通文本输入。
- 选择过程不上传、复制、移动文件，也不改变 NAS ACL。
- 按钮具备可访问名称、悬浮提示和键盘触发能力，彩色 logo 在主题和 iframe 宿主下显示正常。

### FNOS-001-12 上下文文件访问代码完成，待真实 NAS 验收

已完成插件侧路径打开适配和本地验证，尚未在真实 fnOS NAS 完成上下文文件点击和文件应用打开验收：

- DSH 上下文、工具结果和生成文件中的现有路径入口仍可使用，不增加重复 UI。
- fnOS iframe 内直接调用 `TrimApp.openFile(path)`，由 fnOS 文件应用和当前用户权限执行最终判断，不再依据插件授权目录列表预先拦截，也不再触发 NAS 上的 `xdg-open`。
- SDK 不可用或文件应用打开失败时保留可理解的 DSH 错误/重试入口。
- 独立浏览器继续走 DSH 原生打开逻辑；插件卸载或生命周期销毁后恢复原始 `workspaces.openPath`。
- Host 不向浏览器返回 Token、Socket 或内部错误堆栈。

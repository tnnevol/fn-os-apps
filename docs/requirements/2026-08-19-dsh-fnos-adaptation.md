## 需求背景与目标

DeepSeek Harness（DSH）原生面向通用 Node.js 和浏览器环境。作为 fnOS 应用运行时，它需要通过 iframe 进入 NAS 桌面，并同时处理应用生命周期、持久化目录、统一网关和 fnOS Web SDK 的宿主差异。如果这些能力直接散落在 DSH 页面或修改官方源码，后续升级会难以维护，也无法复用到其他 fnOS 能力中。

本需求建立一个专门面向飞牛 NAS 的 DSH 适配层：由 `fn-deepseek-harness` 提供应用运行边界，由 `@tnnevol/dsh-fnos` 和 `@tnnevol/dsh-codex-auth` 提供插件能力。适配层应保持 DSH 官方功能和数据结构不变，只在 fnOS 宿主中增加必要的桥接、授权和 Codex 登录能力。

## 需求目标

- 让 DSH 在 fnOS iframe 应用中稳定启动、访问和持久化运行。
- 将 fnOS 与 Codex 适配能力集中在独立插件中，避免修改官方 DSH 源码；只有已发布并进入 FPK 发布清单的插件才通过 npm 自动集成，未发布插件不进入 FPK。
- 让 DSH 的“跟随系统”主题跟随 NAS，用户明确选择浅色或深色时仍以 DSH 配置为准。
- 让用户能够管理 DSH 访问 NAS 所需的授权目录，并为后续工作区能力保留清晰的授权边界。
- 在工作区选择弹框中提供跳转到已授权 fnOS 目录的快捷入口，授权目录较多时仍能快速检索和定位。
- 在 DSH 内容输入框右下区域提供选择 NAS 目录和文件的快捷入口，将选择结果作为输入引用回填。
- FPK 安装阶段按发布清单自动集成插件：通过安装向导选择的 npm 源安装精确版本，未发布插件不在构建阶段编译、打包或复制到 DSH Web profile。
- 为后续接入其他 fnOS JS SDK 能力保留清晰的 Host、Client 和应用权限边界。

## 交互和行为约束

### 主题

- 进入 fnOS 应用时读取 NAS 当前主题作为初始状态。
- 只在 DSH 主题设置为“跟随系统”时响应 NAS 主题变化。
- 使用 fnOS SDK 的主题事件监听，不增加轮询兜底。
- 在独立浏览器运行 DSH 时找不到 fnOS SDK，适配层应安全降级，不阻塞 DSH 工作台。

### 授权目录

- 入口文案统一使用“授权目录”。
- 展示已授权目录，并提供“添加授权目录”入口。
- 授权目录变化成功后立即重新查询真实授权结果，不设置虚假的保存、取消或恢复按钮。
- 授权列表合并 `TRIM_DATA_ACCESSIBLE_PATHS`、`TRIM_DATA_SHARE_PATHS` 与 fnOS 授权 API 后去重，并使用 `trim.file.convertPath` 展示可读路径。
- `TRIM_DATA_SHARE_PATHS` 中的应用共享目录仅用于展示，不显示删除/取消授权入口，也不调用取消授权 API。
- 取消目录选择器、关闭弹框或返回空授权结果时静默结束，不显示权限角色类红色警告。
- 删除前必须明确提示“只取消应用访问权限，不删除文件”。
- 普通用户可以查看授权结果；添加和删除操作由 fnOS 权限控制。

### FPK 安装阶段集成插件

- FPK 只打入已发布插件的精确版本清单和通用安装脚本，不复制任何插件工作空间源码或本地构建产物。
- `cmd/install_callback` 在 DSH Web profile 尚未初始化时先完成初始化，再使用安装向导选择的 npm 源安装发布清单中的插件，并将包加入 `dsh.profile.bundles`。
- 升级流程按清单从 npm 更新已发布插件；应用启动只校验清单插件的精确版本和 bundle 声明，不因每次启动联网。
- 安装和升级流程必须可重复执行，不能覆盖用户的 DSH 配置、会话、凭据或其他 profile 数据；npm 安装前将有效的本地 `@tnnevol/dsh-fnos` `link:` 依赖规范化为 `file:`，仅将路径失效或旧 patch 不可用的插件从 bundle 列表移除，不删除插件包或用户数据；npm 安装失败时应用安装/升级失败并输出明确日志。
- FPK 安装完成后，发布清单中的插件应能随 `dsh web` 自动加载；未发布插件不属于 FPK 自动安装范围。

### 工作区快捷跳转授权目录

- 保留 DSH 原始工作区选择弹框、菜单、关闭和选中后的跳转逻辑；插件只占用官方公开的 `conversation.hero.workspace.directoryFlow` 与 `sidebar.workspaces.directoryFlow` 子流程插槽。
- 目录流程展示当前有效授权目录，数据与 fnOS 设置中的授权目录列表保持一致，并进行规范化去重；列表展示语义路径，内部保留对应真实路径。
- 授权目录超过 10 个时显示搜索输入，可按语义路径或真实路径检索；少于等于 10 个时直接展示目录列表。
- 底部的 fnOS logo 按钮用于“选择其他目录”，调用 fnOS `pickUserFile({ directory: true })`；选择结果仍通过 DSH 原始 `onPicked` 回填。
- DSH 收到 `onPicked` 后，已有路径复用已有工作区，尚未登记的路径由 DSH 原生流程登记为工作区，再打开对应工作区；插件不修改 ACL、不复制文件、不改变会话数据。
- 授权被撤销、目录不存在或真实路径不可访问时保留原始弹框并显示可理解的错误；取消流程、关闭弹框和选择器取消不产生额外红色提示。

### 内容输入框选择 NAS 目录和文件

- 在 DSH 内容输入框右下操作区域增加有颜色的 fnOS 官方 logo 按钮，使用彩色官方 logo，不与工作区入口共用黑白图标资源。
- 点击按钮后调用 fnOS iframe 宿主提供的目录/文件选择能力，支持选择 NAS 目录和文件。
- 支持多选目录和文件；文件选择调用 fnOS SDK 的 `multiple` 参数，目录选择遵循 SDK 的单目录限制并允许连续选择多个目录，选择结果在输入框文案上方的引用区合并展示。目录使用文件夹 icon、文件使用文件 icon；选项较多时堆叠展示，鼠标移入后展开到输入框可用的最大宽度并支持横向滚动。
- 每个已选项支持移除；按规范化真实路径去重，不允许同一文件重复选择。选择成功后插入 DSH 原生引用占位，展示文案保留可读的语义路径；提交或复制时由引用 codec 生成 URL 转义后的真实 `file:///...` 路径。
- 不自动上传、复制或移动 NAS 文件；选择结果只作为 DSH 支持的路径/文件引用。
- 选择器取消、关闭或返回空结果时静默结束；fnOS SDK 不可用、权限不足或选择失败时保留可理解的错误状态和重试入口。
- 按钮和选择器应适配浅色、深色和 fnOS iframe 宿主；独立浏览器缺少 fnOS SDK 时安全降级，不阻塞 DSH 内容输入。

### 上下文文件访问

- 不增加新的文件打开按钮，继续使用 DSH 现有上下文文件、工具结果和生成文件路径的点击入口。
- DSH 将相对路径解析为工作区对应的真实路径后调用统一的 `workspaces.openPath(path)`；`@tnnevol/dsh-fnos` 在 fnOS iframe 内装饰这个公开服务入口。
- 在 fnOS iframe 内，插件先通过 Host 同源路由校验目标路径是否位于 fnOS 当前授权目录、`TRIM_DATA_ACCESSIBLE_PATHS` 或 `TRIM_DATA_SHARE_PATHS` 根目录内，校验通过后调用 `TrimApp.openFile(path)`。
- 打开目录或文件均交给 fnOS 文件应用处理；插件不调用、不安装也不依赖 Linux `xdg-open`，避免 NAS 环境缺少该命令导致 `ENOENT`。
- 路径未授权时保留 DSH 原有错误/重试交互，并提示用户到「设置 → 插件 → fnos → 授权目录」添加目标所在目录；取消或关闭授权入口不产生额外红色权限提示。
- 在独立浏览器或本地 DSH 调试环境中，插件不执行 fnOS 授权校验，继续调用 DSH 原生打开逻辑，不影响官方本地调试。

#### 用户交互流程

```text
用户点击 DSH 上下文/工具结果/生成文件中的路径
  └─ DSH 解析工作区相对路径并调用 workspaces.openPath(真实路径)
       ├─ 独立浏览器：继续使用 DSH 原生打开逻辑
       └─ fnOS iframe：Host 校验路径授权边界
            ├─ 未授权：提示先到“设置 → 插件 → fnos → 授权目录”添加目录
            └─ 已授权：TrimApp.openFile(真实路径)
                 ├─ 文件/目录打开成功：返回 DSH 页面
                 └─ 打开失败：保留 DSH 错误/重试入口
```

交互约束：

1. 用户继续点击 DSH 原有路径链接，不增加第二个打开按钮，也不要求复制 NAS 内部路径。
2. 取消授权目录选择器、关闭弹框或返回空结果时静默结束，不出现“只有 NAS 管理员可以授权目录”等红色提示。
3. 真实路径只用于 Host 校验和 fnOS 打开调用，不展示 Token、Socket 或内部堆栈。
4. 打开文件或目录不修改 DSH 工作区、会话、配置和 NAS 文件内容。

## 不在本次范围内

- 不修改 DeepSeek Harness 官方源码，不向官方仓库提交适配代码。
- 不改变 DSH 的 `HOME`、`DSH_HOME`、`@appshare` 数据布局和已有会话数据。
- 不因取消授权删除目录、文件、工作区记录、会话或其他用户数据。
- 不通过插件重写 DSH 的 memory 模式、官方插件加载机制或模型业务逻辑。
- 不使用轮询模拟 fnOS 主题事件，也不在浏览器端暴露 `TRIM_API_TOKEN`。
- 不在本需求中一次性接入所有 fnOS JS SDK；每项新增 NAS 能力都应有独立需求和计划。
- 替换整个 DSH 工作区菜单、限制所有工作区只能落在授权根目录内，不属于本次需求范围；FNOS-001-10 只替换原始弹框内部的公开目录流程，不修改官方 DSH 源码，并保留 DSH 原生工作区登记/复用语义。
- 不在 FNOS-001-11 中实现文件上传、文件复制/移动、NAS ACL 修改或会话附件持久化策略；这些能力如需接入应另立需求。
- FNOS-001-11 首期不支持多选结果的批量上传或会话附件持久化；多选仅用于生成 DSH 可消费的路径/文件引用。
- FNOS-001-12 不修改 DSH 官方文件打开实现，不通过安装 `xdg-utils` 解决 NAS 缺少 `xdg-open`，也不绕过 fnOS 授权目录边界。

- “选择其他目录”使用 fnOS 目录选择器，取消时静默结束；加载失败、授权目录失效和选择失败保留可理解的错误状态。
- 应用 bundle 禁用官方自动目录选择器，避免其 Client 目录流程与 fnos 插件重复占用同一插槽；同时只注入官方 `@deepseek-ai/dsh-host-directory-picker-browse` Host 后端，保证 rc.8 的 `dsh-host-apiproxy` 仍能获得 `directoryPicker` 服务。fnos 插件继续独占 Client 目录流程，不修改官方 DSH 源码。

### FNOS-001-11 内容输入框 NAS 选择代码完成，待真实 NAS 验收
